## Frozen path and coalescing

Source file hashes are pinned in `evidence.json`; all paths below are relative to the immutable Unreal fixture.

- `tools/unreal-gdi.js:installObserver` wraps `built.imports.host.gdi_surface_upload` before invoking the original via Reflect.apply. It samples time, copies arguments and increments a sequence before the original call; it records no guest API/callsite, return status, source HDC or frame serial. Lifecycle is captured from installation; uploads only while armed. Thus one retained upload equals one originating import invocation, before RPC or page success.
- `src/09a4-handlers-gdi.wat:359–408`, `$handle_BitBlt`, resolves source/destination descriptors, rasterizes and calls `$gdi_geometry_present` once when `$ok` is true. That helper (`src/10g-gdi-raster.wat:204–221`) normalizes the requested rectangle and calls `$gdi_write_surface_upload`; the latter (`:7634–7648`) performs write notification then the host import. This supplies a concrete path from successful BitBlt rasterization to one observed request. It does **not** establish that this run's requests all followed that path: PatBlt, StretchBlt, shape writers and DIB/palette operations also reach the upload boundary.
- `lib/guest-rpc.js:742–750` makes `gdi_surface_upload` asynchronous and returns1 locally. `postAsync` (`:325–330`) appends each id/args pair to a batch; it is batching, not a game-frame grouping or a page completion receipt. The originating wrapper is upstream of it, so page timing cannot replace the recorded source clock.
- Page handler `lib/host-imports.js:2693–2713` validates the presentation, clips the rectangle, may reattach it to the window, increments its version and calls `surface.markDirty`. The original call can return0 when missing/attachment fails; the current pre-call observer does not capture that page result, and the asynchronous worker return1 is not proof of page success.
- `lib/gdi-surface.js:308–329` unions dirty rectangles until `takeDirtyRect()` consumes them. `_flushGdiSurfacePresentation` (`lib/host-imports.js:374+`) reads then-current canonical memory into ImageData and updates the derived canvas. Multiple earlier requests can therefore contribute to one flush, and intermediate pixels may already have been overwritten.
- `lib/renderer.js:3320+` coalesces already-scheduled repaints, can defer publication during guest work and otherwise schedules requestAnimationFrame. A flush/composition callback is a separate observation from guest rendering and is not necessarily a unique displayed frame.

## Retirement and observation cost

The one worker has both `armed:true` and `stopped:true` receipts in final metadata; `observerStop` is retained, `armed:false`, with finite start/stop and no loss. Its retirement event is explicitly `duringWindow:false`. Driver `endObservation` stores the stop snapshot, turns `observationActive=false` and validates matching arm/stop context sets before later cleanup. The driver then closes the browser; its generic worker-destroyed handler emits “retired before final observation” whenever retirement occurs outside the active window, even after a completed stop. Therefore this warning does not invalidate the already serialized completed window. It also does not prove unknown future windows would have complete coverage.

Minimal bookkeeping correction in a future separate fixture: classify retirements as in-window, before-arm or after-successful-stop/cleanup using the existing record flags; retain all events, and fail measurement only for a coverage gap intersecting the intended window. Do not simply discard retirement diagnostics globally.

The observer allocates/copies event objects and args, samples a clock and serializes history at arm/stop. It performs no pixel read or flush, but overhead is nonzero. It is bounded at100000 retained events and counts drops; overflow or clock errors must reject an admitted metric. Fullscreen pixel conversion/dirty flushing remains application execution cost, whereas optional callsite tracing or image checks are added observation cost. Neither is subtracted here. Browser SwiftShader identifies browser software rendering/composition, not the guest's software rasterizer as a hardware GL workload.
