## Source path and exact semantics

Frozen `src/10g-gdi-raster.wat:5999–6010` calls `$gdi_raster_bitblt`, then on success calls `$gdi_geometry_present` once with the destination operation rectangle. That adapter (`204–221`) normalizes signed extents and delegates to `$gdi_write_surface_upload` (`7634–7648`), which notes canonical memory writes before invoking the host upload. StretchBlt and other raster operations also use the adapter. Lines/palette changes and other writes can produce additional uploads: the hook does not encode the API that caused each event.

The rectangle is a **requested dirty extent**, not a certificate that every pixel changed. Clipping can update only part of a nominal full-size rectangle, including the complex-clip case documented for Collapse. The destination may be a memory bitmap, child/control surface, DirectDraw backing surface, or top-level window. A full 800×600 rectangle alone is insufficient selection evidence.

`lib/guest-rpc.js:742–750` sends each upload once via `postAsync` and immediately returns **1**. This is an optimistic transport return, not page-side success. Observer code should record before forwarding and preserve arguments/result. No second raw upload is emitted merely by broker delivery; `serveCalls` invokes each queued pair once. Do not collect the same call both in the Worker and page and add counts. Separate guest workers can independently draw into one surface; preserve their identities rather than silently merge raw clocks.

Page-side `lib/host-imports.js:2693–2715` resolves the surface, clips bounds, optionally attaches to its HWND, increments presentation version, and marks the rectangle dirty. Missing surfaces/failed attachment return 0; an empty clipped rectangle returns 1 without marking dirty. Multiple uploads are coalesced by canonical dirty rectangles before presentation. This explains why submission counts can exceed displayed updates without a collector bug.

`_flushGdiSurfacePresentation` (`374–438`) takes pending dirty bounds, converts/copies pixels with putImageData and increments `flushCount`. It calls `_noteGuestFrame` for non-DirectDraw surfaces only while DirectDraw presentation is inactive. A clean flush returns without counting. `canvas._waFlushCanonicalSurface` is called by renderer composition (`lib/renderer.js:603–604`), but wrapped `getImageData` also flushes (`host-imports.js:2667–2671`): readback/screenshot probes may induce flush work. Initialization seeds a dirty full surface. Therefore canonical flush counts describe **host cache materializations**, not originating guest frame cadence. They can include offscreen/readback work unless independently filtered. No GDI equivalent of the previously found extra DX-wrapper callback was found: `host.js` adds a wake on upload, whereas its extra `onGuestFrame` call is conditional on DX trace kind5/6. Still, public GDI callback omits surface identity and is the wrong originating timestamp hook.
