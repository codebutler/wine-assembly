## Measurement contract for any granted experiment

Pin servedsource/module/EXE/assetidentity, browser/V8/architecture/GPU/backend and ownerthread mode. Measure active equivalent ordinaryinputscene, correctcompletionandoutput first; separate load, menuidle and gameplay. Wholeprocess/wholeChromeCPU includes Workers and build/JIT; main slice alone omits audio. Use repeated rotatedpairedarms and off/offnullband, isolated serialresourceownership, warmup declaredbeforehand. Report milliseconds/CPU and logicalsubmissions/displayFPS separately; batches and handlercounts are notwork-normalizedFPS. Save failures, cappedtraces and missingraw honestly. Firstexperiment should reject a hypothesis cheaply before any broadengine rewrite.

Additional direct harness check: current `tools/toyvm/arm-bench.js:219` retains **best CPU time per arm across repetitions**, not the complete paired distribution. Arm ordering rotates by program and repetition, but the output JSON's per-arm value is selected best-of. Its `run` ratio subtracts reported build CPU from whole CPU; it is not an independently isolated steady-state timer. Recover console/per-repetition logs if available before deriving confidence, null bands or precise regression sizes from that latest aggregate. This reinforces, rather than reverses, the recommendation against promising a transferable JIT speedup.
