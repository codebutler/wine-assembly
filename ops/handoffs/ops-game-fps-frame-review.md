**Kind 5 counts emulator presentation requests, not necessarily completed game frames. A single stable primary slot is insufficient to establish FPS. Kind 6 is the stronger accepted Flip boundary, but still precedes actual host composition and may precede rendering completion.** Never use `WineHost.onGuestFrame` as an exact counter: its frozen callback wiring duplicates kind 5 notifications.

Kind 6 arguments are `(6, frontSlot, backSlot, newFrontDib, oldFrontDib)`. In the queued branch the last two values describe the planned swap, read before the render worker performs it. Vblank wait/park and `DDFLIP_DONOTWAIT` failure occur before either emission; a no-backbuffer successful empty Flip produces neither. Neither branch validates that every accepted Flip contains distinct new game content. The first accepted Flip with pending draws can queue; the next fence drains it. See `d3dim_worker_try_flip` at core lines 130–144 and `d3dim_worker_fence` at 84–93.

Consequently one logical frame may generate several kind-5 events on exactly the same front slot: partial blits, rect unlocks, palette writes, and final Flip. A synchronous Flip alone generates kind 6 plus kind 5. Equal pixels can be presented repeatedly. Conversely held intermediate scroll frames suppress kind 5. Do not deduplicate by timestamp, slot, DIB pointer, or pixel equality: each would invent a content/frame definition not present in this protocol. `present_pace_note` comments at DirectX 3665 explicitly acknowledge some apps present twice per frame; kind 30 is emitted only while a cap is enabled and is not a replacement general counter.

## Worker forwarding and host/render layers

1. `lib/guest-worker.js:407–419,438` builds one `GuestRpc.createWorkerImports` table per guest Worker and passes it to instantiate. The correct observer wraps **that originating `built.imports.host.dx_trace`** exactly once before instantiate, preserving all arguments and return behavior. Include run ID, Worker context identity/generation, RPC thread slot and monotonic sequence number. RPC slot is a guest-thread identifier, not the `dx_trace` surface-slot argument.
2. `lib/guest-rpc.js:699–740` locally filters high-volume DX traffic, but forwards each kind 5 and 6 once through `postAsync`. First-sighting logic sets a boolean; it does not send a second copy of the same event. With filtering off, `dx_trace` is still an asynchronous allowed import. `postAsync` batches at 256 calls or elapsed-threshold checks and flushes before other messages (`305–331`); it is not a timestamp-preserving presentation clock, nor a timer promising delivery within 4ms during a stalled caller.
3. Each guest worker posts `{t:'calls', slot, list}` to its owner. `lib/guest-thread-host.js:163–164` serves that batch once; `guest-rpc.js:973–986` invokes each pair once. There is no normal broadcast/replay across guest workers. Separate guest threads can independently present the same shared DX slot. Browser broker tables are shared (`824–834`), so intercepting only the page table loses originating context and measures batched delivery, not event time. Preserve worker clocks separately; never merge raw `performance.now()` values from different origins.
4. `host.js:1376–1394` marks DX dirty and invokes `self.onGuestFrame` once for **both** kind 5 and 6, then forwards to the raw host import. Default `lib/host-imports.js:1747–1753` calls `_noteGuestFrame` again for kind 5; `ctx.onGuestFrame` routes that back to the same `self.onGuestFrame` at `host.js:1278–1279`. Thus a usual synchronous Flip can generate **three** public callbacks: 6, 5, 5. This is callback duplication, not duplicate raw WAT events or worker-forwarding duplication. DX tracing replaces the raw hook (`host-imports.js:3132,3162`) with logging and different callback behavior, so enabling trace also changes this proxy's behavior.
5. `dx_present` then binds canonical surface `0x200000+slot`, attaches and uploads, or copies into a window/shared surface (`DirectX 6337–6440`). Multiple dirty uploads may coalesce before composition. `host.js:1409` onward explicitly limits upload opportunities with RAF. `_noteGuestFrame` excludes GDI surface flushes once DX presentation activates (`host-imports.js:178–190,429–435`), preventing one known extra category of counts; it does not turn every primary request into a whole game frame.
6. The D3DIM render worker uses inert host imports (`lib/d3d-render-worker.js:59–65`). Its `d3dim_worker_flip` export only swaps DIB pointers (`core:146–151`) and does not emit kind 5 or 6. Deferred kind 5 originates later from the guest-side fence. No raster-worker duplicate stream was found. GPU/Glide `onPresent` hooks are separate and must not be mixed into this DirectDraw stream.

## Honest measurement contract

For a single verified context/front and stable scene, **guest Flip submissions per wall second** is defensible for kind 6. Dashboard `metric:"guest-presents"` may describe that stream only with explicit notes: accepted Flip events, selected front/context, originating Worker wall clock, not displayed/unique-content frames. A kind-5-only stream can be called **emulator present requests per wall second**, but cannot qualify as gameplay frame FPS from this hook alone. Demonstrating a true full-frame source would require a separately reviewed observational method; do not guess addresses or infer one frame from regular timing.

Arm and stop inside the same originating context. Use actual `[start,stop)` monotonic bounds, count all selected events in that interval, duration `stop-start`, FPS `1000*N/durationMs`. For p95 use only successive selected-event gaps whose two endpoints both lie within the same window; no pre-arm/post-stop or inter-window gap. Record nearest-rank convention and interval count. Retain raw finite timestamps; clock regressions invalidate the sample. If clock quantization produces zero intervals, record their count and either include them in a clearly defined full event-gap distribution or mark the requested positive-interval p95 unqualified. Silently dropping zeros can bias p95 and hide bursty submissions. Do not substitute 1000/FPS for an interval statistic. Wall time includes guest stalls/scheduling; it is neither guest virtual time, CPU time, batch time, RAF cadence nor hardware refresh.

Loading/menu/pause/end-of-life/new-round frames do not qualify.
