## Concrete prototype and admission

`observer.js` derives DxObject32byte layout from exact frozen declarations and reads DX_OBJECTS/DX_SURF_OWNER using supplied RegionMap and DataView. Double reads retain consistent/inconsistent markers; no guest export, memorywrite, flush, atomics, RPC or logging. These are observational snapshots, not locks. Initial primary list is captured before that worker begins guest execution, even if another worker has already created a primary. This avoids treating late worker's existing primary as missing its own allocation.

Each origin gets a unique generation/context ID and threadSlot, independent clock, monotonically increasing relevant-event sequence, complete capped5/6/21/22 history frominit (not reset by arm), initial/arm/stop primary snapshots and sequence cuts. The synchronous import wrapper forwards original this/arguments/result/exception unchanged and captures observation failure as diagnostics; bounded overflow/read errors fail admission. Stop returns a deep immutable copy, preventing browser.close from mutating the reviewed evidence later. History means all four relevant event kinds, not every dx_trace kind.

Admission requires every registered guestcontext's complete history/endpoints, unique context/threadslot identities and registration before its execution. Two workers are supported directly; no single-worker gate simply removed. Late initialization **before arm** may show the same live primary. Exactly one selected-slot allocation must be witnessed in a context whose initial primary list was empty and before that context's arm. Any selected-slot free or second allocation anywhere in retained histories rejects attribution, even outside the short window: deliberately conservative unknown-generation/ABA rejection. Any lifecycle callback during any context's local arm/stop window also rejects this stable-interval proposal. Nonselected historical lifecycle activity remains retained for review; no invented cross-origin merge order.

All initial nonempty/arm/stop/selectedevent snapshots must consistently identify the same slot/liveprimary and stable owner/misc0/dimensions/bpp/pitch/flags. Backbuffer bits misc1 may alternate onFlip and are required nonzero, not incorrectly frozen. Require640x480 for this observed GTA route. Missing/gapped/overflow histories, bad local time ordering, inconsistent reads, differing primary observations, absentallocations, selectedreuse/free, unknownworkers and during-window creation/retirement reject. Exactly one originatingFlip producer is required for this slice; otherworkers still contribute lifecycle. Producer local events must alternate6,5 onselectedslot; noclockmerging or crossworkerFPS sum. This is callback pairing, not proof of unique logical frames.

Coverage is supplied from page workercreated/workerdestroyed registration beforelaunch. Capture immutable phase values and immutable stop snapshots; freeze assessment before cleanup begins. Retirement in explicit `cleanup` phase does not poison an already saved stop; before/duringwindow retirement or missingstop does. `captureComplete`/registration fields are an integration contract to prove with page events, not booleans the helper can infer or authorize setting true. A context created during the window fails and ends qualification; do not silently add it or count only contexts with nonemptyFlip rows.

## Atomicity/ordering limits and smallest extra observation

Allocation21 is emitted after releasingLOCK_DX, free22 after clearingwrites; another worker may observe mutation while publisher is descheduled before its hook. Allocated records can be partially initialized. Double reads can agree across an ABA cycle and don't establish an atomic global snapshot. Trace hooks do not observe every primary-flag/globalselection change. Per-context arm/stop calls are sequential, not simultaneous; no common measured interval is fabricated. Proving lifetime globally by sorting worker clocks or assigning a shared host atomic ticket **at hook time** would not fix those publication gaps.

For the next bounded diagnostic, existing hooks plus conservative union-of-complete-histories and local snapshots are sufficient to establish only **observed** selected-surface stability with explicit limits. Preserve original ordinary route and before/after human-reviewed world evidence; do not impose an unrelated global scheduler rewrite merely to obtain that diagnostic. Strict mutation-linearized generation proof, if later required for a stronger claim, needs an additional authoritative observation: e.g. shared monotonic per-slot generation/revision updated at all guest allocation/free/primary-transition mutation sites (inside appropriate existing locking rules), read with a stable revision at endpoints/events, plus coordinated worker coverage. That would be a separate reviewed source/build task. Do not move host RPC imports insideLOCK_DX or pretend existing mutating accessor is a pure snapshot. No such extra instrumentation is authorized or implemented here.
