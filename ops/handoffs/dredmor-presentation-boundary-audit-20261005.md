The existing11.8/s sample remains two diagnostic rates: guest render tails and selected canonical window uploads. It cannot be relabelled as game-presentation FPS. A minimal new measurement can count **new SDL client generations successfully composited to the application display canvas**, with coalescing explicitly allowed, without asserting physical scanout or one display per SDL_Flip.

Add only private observer metadata at the owning import-publication seam and corresponding broker-consumption seam, with monotonic per-owner sequence and real dispatch caller/stack proof. Coalesced sequences1,2,3 followed by one successful canvas draw count as **one presentation**, explicitly record two coalesced submissions. Repeated compositor passes of sequence3 count zero. No requirement to force one-to-one with guest tails.
4. Increment only after normal browser CanvasSurface.drawImage completed without exception and the containing compositor pass finishes with client visible/unobscured. Reject hidden/minimized/occluded/clipped client, overlays, other target writes during the generation, context loss, failed canonical flush, changed canvas/owner/size, unsupported RasterSurface or exclusive mode. Fail closed rather than count partial frames. No forced flush/readback/screenshot during timed sample; those are outside it.

Report successful coalesced SDL client presentations/second, rendered/submitted counts and coalescing separately. Physical display FPS remains null; no scanout, VSync or unique-content claim. A static room can redraw identical game frames, so retain existing qualified gameplay/input evidence and a small ordinary input trace without treating another screenshot as new qualification.

Preserve exact receiver/arguments/return/error behavior. Test publication ordering with the actual RPC broker, not a fabricated synchronous queue. Counter cap/replacement safeguards remain from existing adapters.
