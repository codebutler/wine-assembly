## API and integration

- `workerOverlay(frozenWorkerSource,{runId,capacity:100000})` returns a served-only overlay at the unique frozen `WebAssembly.instantiate(msg.module,built.imports)` seam. It installs `globalThis.__collapseGdi` and wraps the four actual originating imports once. Pass the full assigned run/task/thread identity in runId; context identity additionally contains guest RPC slot and Worker timeOrigin. Keep original/served hashes. No module/host modifications or source-tree copy are needed.
- `installObserver(host,options)` is self-contained and serializable. It preserves arguments, receiver, exact result object/Promise and original exception. The original call executes once. Clock failures are recorded without suppressing original forwarding. No per-event RPC, log, pixel read, timer or flush is introduced.
- Call `__collapseGdi.arm()` then `stop()` **in each originating Worker** for one bounded diagnostic window. Each uses that context's monotonic clock; returned snapshot contains thread/context identity, raw sequence, timestamps, full argument arrays and inWindow flag. Uploads are recorded only while armed. Create/attach/delete notifications are retained from installation, including before arm and after stop. Single-window admission is deliberate; rearming throws instead of erasing lifecycle evidence.
- One shared event cap covers uploads and lifecycle records; overflow increments `dropped`, never silently evicts. A long startup can fill the cap before arm, in which case qualification fails visibly. Invalid/regressing clock observations increment `clockErrors`; zero inter-upload gaps fail distribution admission. No clocks are merged.
- `pageMetadata(wine)` is self-contained and can be serialized into a page evaluation, called with the actual `runningApps` entry's `.wine`. It reads **`wine.hostCtx.sharedGdi.surfacePresentations`** and **`wine.hostCtx.renderer.windows`**, filtering surfaces by `presentation.surface.storage.buffer === wine.memory.buffer`. These paths are confirmed by frozen host.js1354/3895–3904 and host-imports.js2659–2671. It reads IDs, dimensions, backing pointer, target HWND, DirectDraw/desktop/overlay flags, window title/visibility/child/parent metadata. It never calls flush/getImageData/renderer methods. Return `available:false` is an explicit missing-observation result.
- After reviewing the actual top-level Collapse board screenshot and page metadata, supply `diagnose(snapshots,{reviewed:true,evidence:'artifact + window association explanation',surface:<selected page metadata record>})`. There is no automatic game/window/title certification. Selection rejects child/desktop/overlay/DirectDraw, hidden or unassociated surfaces, missing review evidence, duplicate contexts, overflow/bad windows, missing uploads, multi-context upload streams and any selected-surface create/attach/delete event in the window. This lifecycle rule is intentionally conservative, including repeated attach/create calls; do not quietly relax it during integration.

Diagnostics retain full/partial/covering-clipped/outside/invalid-or-empty request counts per context and in total. Mixed rectangle classes are evidence, not automatic FPS. `associationAccepted` means the limited supplied association/buffer checks passed, **not** that the surface generation or scene has been universally proven. Every output retains `diagnosticOnly:true`, `performance:null`, `gameplayCertified:false`. No FPS or percentile calculation is implemented.

## Tests and scope limits

Tests exercise exact forwarding/receiver/result/exception, idempotent installation, clock-failure forwarding, lifecycle retention, source-clock bounds, full/partial/clipped/empty classes, explicit association, multi-context rejection, selected versus unrelated lifecycle, zero events/gaps, overflow, regression/nonfinite/outside timestamps, page-memory ownership and no-flush metadata reads. Static checks parse the actual frozen Worker overlay and assert observer source has no per-frame messaging/logging/pixel operations.

The hook observes **requested dirty uploads**, not page success: frozen guest RPC returns optimistic1 and batches forwarding. Full rectangles may have been clipped or contain unchanged pixels. Create/attach/delete events are raw calls; original failure results are forwarded but not interpreted as lifecycle success. Current diagnosis conservatively invalidates activity rather than assigning a fictitious generation. Multiple workers can operate on shared surfaces, so the integrator must enumerate all app guest contexts and retain startup/retirement/coverage evidence; this library cannot discover missing contexts by itself.

Metadata is a point-in-time observation, not an atomic whole-process snapshot. The integrator must retain before/after association evidence and reject rebinding or changed geometry outside the observer's covered window; the helper does not stitch snapshots from unrelated pages. It does not replace the reviewed normal-click/board/score qualification gates or the original outer deadline and own-resource cleanup. Keep measurement disabled and do not publish performance from this diagnostic.
