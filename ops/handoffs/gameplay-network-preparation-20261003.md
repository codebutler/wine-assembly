## Transport and isolation

Use one browser/page with the existing **VlanWire.LoopbackSegment**, one endpoint per app process and explicit addresses10.0.0.1/.2/.3. Existing `launchApp(appKey,{lanLink:{wire:segment.attach(),address,local:true}})` supplies the network before guest initialization and permits multiple same-app instances. `lib/browser-shell.js` disables automatic room discovery when lanLink is supplied; `host.js.joinVlan` is the established transport hookup. No WebRTC room, signaling service, remote host, chat message or external account is needed. This is harness setup of virtual peers, not guest state injection. Actual game hosting/joining must use visible game UI.

Guard outgoing browser requests to the loopback static origin; save rejected requests rather than silently allowing external room discovery. Keep the host-supplied explicit LAN link through launch and verify endpoint/IP identity per process. Do not use the lobby's automatic “both players here” action for SC2K: it creates a second copy of the same app, whereas SC2K requires one different server app plus two clients.

Each WineAssembly process reserves512MiB shared WASM memory; two seats reserve1GiB, three1.5GiB plus renderer/browser overhead. This is one coordinated multi-process runtime slot, with two/three main Workers and possible guest-created auxiliary Workers—not the one-Worker restriction of the unrelated JigSawedME diagnostic. Use one loopback static server, one browser and one page with shared compositor. Bring the target game window forward by ordinary taskbar/window clicks before typing; save actual HWND/process/focus mapping. Do not assume two windows share keyboard ownership.

Cleanup must run in finally: stop every launched WineAssembly instance, terminate its guest Workers, close all page/browser resources, clear observer/timer handles, release loopback endpoints/segment references, close static-server connections/listener, await pending response saves, and record process check. LoopbackSegment has no detach API; browser teardown/releasing its references is necessary. Preserve every failed seat's screenshot/log and declare the whole session incomplete if a required peer dies. No automatic retry. All performance fields remain null.
