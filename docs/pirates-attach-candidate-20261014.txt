Implementation
beginDllThreadNotification owns the callback gate, generation-pinned ordered
snapshot, module cursor, and active dllMainSteps generator across scheduler
turns. The cooperative generator runs one requested quantum and leaves actual
callback EIP/ESP/registers/SEH in place when parked. Only a complete stdcall
return restores its caller; false EAX is a valid thread notification return.
runSlice uses its existing wait polling and post-run accounting for callback
quanta. There is no recursive scheduler pump. The procedure cannot execute
before the notification and its trailing unload continuation finish.

All snapshot pins remain through all attach callbacks. At the end, pins are
released and dllUnloadSteps drives any pending PROCESS_DETACH with the same
cooperative callback runner before the outer gate is released. A blocked
detach retains its reserved group. Fault/ExitThread/cancellation retain the
unfinished attach image's quarantine pin and release the other pins and gate.
_markThreadExited cancels a pending operation, including forced termination;
cancellation inside an executing host import is deferred until run returns.
Cancelled/faulted callbacks do not restore a live-looking thread procedure.

The numeric/synchronous callDllMain and async Worker wrapper contracts retain
their original driver. Nested synchronous COM/LoadLibrary service uses the
existing runSlice resolver while the outer generator and gate remain held.
A resolver failure retires the pending notification before propagating.

Remaining boundaries / no full-completion claim
- Existing synchronous nested-load resolver can still abandon a newly loaded
  initializer that blocks. This patch preserves previously successful nested
  service, but does not implement an arbitrary nested async loader-operation
  stack. Worker asynchronous loading retains its original behavior.
- Thread detach after graceful exit remains the existing synchronous path.
- Process-wide external shutdown has no ThreadManager disposal interface;
  an embedder must retire/cancel pending thread operations before reusing the
  shared process. Dropping live operations without teardown is not supported.
- The baseline tools/pirates-attach-gap.js asserts the OLD manager defect; it
  is a historical witness for base 6aa6d0b7e, not a candidate passing test.
- Runtime below establishes main thread1 owns the observed section and can
  release it. A different genuine guest loader-lock dependency cycle would
  not be fixed merely by preserving a callback.
