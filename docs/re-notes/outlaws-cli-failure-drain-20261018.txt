Outlaws CLI exceptional-exit diagnostics (2026-10-18)

Evidence: scratch/runs/20261018-outlaws-original-qt-observation/review.json
and output.log in the shared repository. The original f7c9f5c module reached
PMPRO62F DllMain -> QT -> win16_dispatch fail-fast. The CLI awaited the loader
outside its batch trap handler, so the rejection bypassed the local buffered
log drain and normal control-stdin close. The owned 85-second watchdog killed
the still-resident process. This did not identify the missing Win16 import.

test/run.js now registers initialized cleanup callbacks with
lib/cli-failure-cleanup.js. On rejection it closes the control channel, flushes
pending trace deduplication, drains existing decoded diagnostics, and rethrows
the same error. Cleanup errors are reported individually without skipping
remaining cleanup or replacing the original error. Normal end-of-loop control
closure remains in place and is not repeated after a later exception. The
top-level rejection handler sets a nonzero exit code before existing worker
and renderer retirement. The failure drain resets the trace-window batch so
fatal diagnostics survive --trace-from/--trace-to filtering. No Win16 behavior or import identity is synthesized;
post-QT frame restoration makes win16_last_module/ordinal unsuitable here.

Pure JS verification: node test/test-failure-cleanup.js exercises async
rejection identity, cleanup failure isolation, reverse cleanup order, success
ownership, and a real child process with open parent-held stdin, readline,
buffered diagnostics, and exit status 1. This tests the cleanup primitive;
it does not by itself prove the full CLI Win16 decoder/loader integration.
