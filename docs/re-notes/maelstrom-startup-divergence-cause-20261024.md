Historical source last updated, 2026-10-24. Runtime and implementation claims below describe that dated source; see current app notes and source for subsequent changes.

Canonical runner `test/run.js` parses five `--trace-at` addresses and unconditionally assigns **`BATCH_SIZE = 1` at lines 1528–1530**. The preceding reached-Sync run specified one trace address and retained the default **1,000** at line 288. The main loop calls `instance.exports.run(BATCH_SIZE)` at line 10363. This is a concrete harness cause of unequal execution budgets, established by evaluating the exact hash-checked startup statements without loading WASM. It is sufficient to reject the latest recipe as a passive follow-up to the earlier run. It does not prove that budget restoration alone guarantees the same entire guest outcome, or identify the precise incoming native call at the final PC. No game, network, interpreter or `_ftol` defect is established.

The checks (historical artifact: `maelstrom-startup-divergence-cause-20261024/checks.json`) retain exact source slices and fragment hashes. `--trace-at-start-batch=36163` delays breakpoint arming at lines 10247–10258, **not** the startup size assignment. `--trace-from=30000` gates logging, not execution size. `--trace-at-limit=16` limits records, not the earlier assignment. 42,000 calls with requested budgets of one versus 1,000 are upper budgets of 42,000 versus 42,000,000 blocks, not measured retirement totals or a claim that total work differs by exactly 1,000. Thus CPU work available before each scripted input and capture also changed. Silently extending the batch ceiling would change the experiment again and is not a correction proposed here.
